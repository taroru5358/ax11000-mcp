# AX11000 MCP 実装計画

- 作成者モデル: muse-spark-1.3-contributor
- 日付: 2026-09-27
- 対象: TP-Link Archer AX11000 (192.168.0.1, gamingテーマ, /cgi-bin/luci系)

## 目的・背景

- 192.168.0.1 の AX11000 管理画面を Chrome 手動操作なしで AI から操作したい
- ユーザー要望: 参照系+変更系+ログ診断系+raw実行、軽量API直結型、stdio、認証情報はファイル保存
- 実機確認済み: `GET /` → `/webpages/index.html`、JS は `$.su` + `tpEncrypt.js` (AES+RSA署名) 系。`tplinkrouterc6u` が Archer AX11000 V1 をサポート明記

## 実装方針

- `tplinkrouterc6u==5.35.0` を利用し暗号ログインを自前実装しない (TplinkRouterProvider.get_client で機種自動判定)
- `mcp>=1.0` の FastMCP (stdio) でサーバ化
- 認証情報の優先順位: 環境変数 > `$TPLINK_ENV` で指されたファイル > カレント `.env` > `~/.config/ax11000-mcp/.env`
  - 変数: `ROUTER_IP`(既定192.168.0.1), `ROUTER_USERNAME`(既定admin), `ROUTER_PASSWORD`(必須), `ROUTER_TIMEOUT`
- ルータは同時1セッション制限のため各ツール呼び出しで authorize→実行→logout (with router パターン)
- Wi-Fi パスワード等の秘密値は既定でマスク (`reveal_secrets=true` で開示)
- 書き込み系 (set_wifi/reboot/予約追加削除) は `confirm=true` 必須の安全ゲート

## 実装ステップ

1. `uv init` 相当の pyproject 作成、deps: tplinkrouterc6u, mcp, python-dotenv
2. config.py: .env 探索・読み込み、バリデーション
3. server.py: FastMCP + 下記ツール群
4. README + .env.example + Claude Code 登録例
5. `uv sync`, `ruff format/check`, `pytest -q`, `uv run ax11000-mcp --help` 相当の起動確認 (実機ログインはパスワード入手後に手動確認)

## MCPツール (初版14)

- 参照: `router_overview`, `list_devices`, `get_firmware`, `get_ipv4_status`, `get_ipv6_status`, `get_dhcp_leases`, `list_reservations`, `get_mesh_nodes`, `get_wifi(band)`, `session_info`, `list_endpoints`
- 変更 (confirm必須): `set_wifi`, `add_reservation`, `delete_reservation`, `reboot_router`
- 保守/汎用: `raw_request(path,data,operation)` — syslog/無線詳細/guest等は機種差があるためraw経由でカバー

## リスクと対策

- 機種ファーム差で一部エンドポイント未実装 → AttributeError/NotImplementedError をツール側で {"supported":false} として返す
- 1セッション制限で Web UI と競合 → 毎回 logout、失敗時は明示エラー
- パスワード誤り・TP-Link ID指定 → Local Password 必須を README に明記
- Chrome MCP が当セッションで利用不可 → curl で実機到達確認済み (HTTP 200, /webpages/index.html)。ブラウザ目視はパスワード入手後の手動確認に委ねる
